## 3. CORE ARCHITECTURE & CODE EXECUTION FLOWS

### FLOW 1: Public Page Rendering Lifecycle
```
1. Client Browser sends HTTP/HTTPS GET request (e.g., https://www.vortexsoftinnovations.com/service.php).
2. Apache reads .htaccess:
   - Enforces HTTPS (301 redirect if HTTP).
   - Enforces www. domain prefix (301 redirect if naked domain).
   - Evaluates URL rewrite rules (converts .html requests to .php).
   - Injects HTTP Security Headers (X-Frame-Options, X-Content-Type-Options, CSP, HSTS, Referrer-Policy).
3. PHP runtime initializes:
   - `config/constants.php` loads -> Dynamically parses `$_SERVER['HTTP_HOST']` -> Sets `SITE_URL`, `PRIMARY_COM_URL`, `PRIMARY_IN_URL`.
   - `includes/header.php` starts output buffering via `ob_start()`.
   - Injects SEO Meta Tags, OpenGraph, Twitter Cards, Hreflang alternates (`en-US`, `en-IN`, `x-default`).
   - Injects Schema.org JSON-LD graph (`Organization`, `LocalBusiness`, `BreadcrumbList`, `FAQPage`).
   - Renders Topbar (Pune HQ & Bengaluru phone numbers, social links) and Sticky Navbar with 4-Column Services Mega Menu.
   - Embeds Inline Page Loader (with 150ms automatic dismissal fail-safe).
4. Page Body executes:
   - Fetches dynamic content from MySQL database via `config/database.php` (e.g., blog posts, job listings).
   - Falls back to SQLite (`sqlite_dev.db`) if MySQL connection fails.
   - Renders HTML sections, CTA banners, and AEO fact blocks.
5. `includes/footer.php` executes:
   - Renders CTA Banner, Animated CSS Trust Marquee (ISO 27001, HIPAA, ISO 9001).
   - Renders 4-column footer links and highlighted Pune Headquarters address with Google Maps link.
   - Loads `assets/vortex-shared.js` (Initializes 3D Particle Cyclone Canvas, IntersectionObserver for scroll reveals, animated number counters).
   - Registers Service Worker (`sw.js` v10) for client-side caching.
```

### FLOW 2: Contact Form Inbound Flow & Anti-Spam Pipeline
```
[User on Frontend] -> Fills Contact Form (#contactForm)
       ↓
[vortex-shared.js] -> Prevents default submit -> Validates required fields & email format via regex
       ↓
[AJAX POST] -> Dispatches fetch to `/api/contact.php` with FormData payload
       ↓
[/api/contact.php Backend]:
  1. Header Validation: Enforces Content-Type: application/json and X-Content-Type-Options: nosniff.
  2. Method Guard: Rejects non-POST methods with 405 Method Not Allowed.
  3. Honeypot Anti-Spam: Checks `$_POST['website_hp']` -> If populated (bot detected), silently returns success without processing.
  4. CSRF Validation: Checks `$_POST['csrf_token']` against `$_SESSION['csrf_token']` using `hash_equals()`.
  5. IP Rate Limiting: Checks `check_rate_limit('contact_' . md5($ip), 5, 300)` (Max 5 submissions per 5 minutes per IP).
  6. Data Sanitization: Runs `sanitize()` (HTML entity encode + strip tags) and `sanitize_email()`.
  7. Input Constraints: Verifies Name (max 120 chars), Email (filter_var), Phone (regex), Message (min 10, max 5000 chars).
  8. Database Ingestion:
     - Prepares SQL: `INSERT INTO contact_inquiries (name, email, phone, service, company, message, ip_address, user_agent, source_page, created_at) VALUES (...)`
     - Executes via PDO prepared statement. Retrieves `inserted_id`.
  9. Transactional Email Dispatch:
     - Calls `send_contact_notification()` -> Dispatches HTML alert email to `support@vortexsoftinnovations.com`.
     - Calls `send_contact_acknowledgement()` -> Dispatches branded confirmation email to visitor with inquiry reference ID.
     - Logs email execution to `email_logs` table.
 10. JSON Response:
     - Returns `{"success": true, "message": "Thank you! Your message has been sent.", "inquiry_id": 142}`.
       ↓
[Frontend UI]:
  - Resets form fields.
  - Triggers Bootstrap Modal (#contactSuccessModal) displaying confirmation feedback.
```

### FLOW 3: Candidate Job Application & Resume Processing Flow
```
[Job Seeker on careers.php] -> Clicks "Apply Now" on job card -> Opens Modal (#applyModal)
       ↓
[User Fills Form]: Name, Email, Phone, Experience, Notice Period, Expected CTC, Cover Letter + Uploads Resume (.pdf/.doc/.docx)
       ↓
[AJAX POST] -> Dispatches multipart/form-data to `/api/apply.php`
       ↓
[/api/apply.php Backend]:
  1. Anti-Spam Check: Verifies honeypot field `$_POST['website_hp']`.
  2. Rate Limiting: Enforces max 3 applications per 10 minutes per IP (`apply_md5($ip)`).
  3. Input Sanitization: Sanitizes all string fields.
  4. File Validation:
     - Checks `$_FILES['resume']['error'] === UPLOAD_ERR_OK`.
     - MIME Type Validation: Must be `application/pdf`, `application/msword`, or OpenXML Word doc.
     - Extension Validation: Whitelist `['pdf', 'doc', 'docx']`.
     - File Size Limit: Max 5,242,880 bytes (5MB).
  5. File Storage & Security:
     - Ensures `/uploads/resumes/` directory exists with `0755` permissions.
     - Enforces `.htaccess` blocking PHP execution inside the directory (`Options -Indexes`, `Deny from all for .php`).
     - Generates cryptographically safe filename: `date('Ymd_His') . '_' . preg_replace('/[^a-zA-Z0-9\-_]/', '_', $name) . '.' . $ext`.
     - Executes `move_uploaded_file()`.
  6. Database Persistence:
     - Prepares SQL: `INSERT INTO job_applications (job_title, department, applicant_name, email, phone, current_location, experience_years, current_company, notice_period, expected_ctc, resume_filename, resume_path, cover_letter, linkedin_url, portfolio_url, ip_address, status, created_at) VALUES (...)`
     - Default status set to `'new'`.
  7. Email Notifications:
     - Calls `send_application_notification()` -> Dispatches candidate dossier to `careers@vortexsoftinnovations.in`.
     - Dispatches branded auto-acknowledgement email to applicant with reference timeline (3-5 business days).
  8. JSON Response:
     - Returns `{"success": true, "message": "Application submitted successfully!", "application_id": 89}`.
       ↓
[Admin Review Flow]:
  - HR Admin logs into `/admin/applications.php`.
  - Filters by job role or candidate status.
  - Updates candidate pipeline (`new` -> `reviewed` -> `shortlisted` -> `interview` -> `offered` -> `rejected`).
  - Clicks "Download Resume" -> Dispatches request to `/admin/download.php?id=89` -> Script validates admin session, verifies file existence, streams binary file with `Content-Disposition: attachment`.
```

### FLOW 5: Admin Authentication, Security & RBAC Flow
```
[Admin User] -> Navigates to `/admin/login.php`
       ↓
[GET Request]:
  - Checks if active admin session exists (`$_SESSION[ADMIN_SESSION]`). If yes, redirects to `dashboard.php`.
  - Generates CSRF token.
       ↓
[POST Submit]:
  1. Rate Limit Enforcement:
     - Key: `admin_login_` . md5($ip). Max 10 attempts per 5 minutes.
     - If exceeded, locks interface and outputs security alert.
  2. Input Sanitization: Sanitizes username and trims password.
  3. Database Authentication:
     - Prepares SQL: `SELECT * FROM admin_users WHERE (username = :u OR email = :u) AND is_active = 1 LIMIT 1`.
     - Executes query against MySQL.
     - Verifies password using `password_verify($password, $user['password_hash'])`.
  4. Fallback Authentication Guard:
     - If database is during active migration, validates against secure fallback hashes for super_admin.
  5. Session Security Initialization:
     - Calls `session_regenerate_id(true)` to prevent session fixation attacks.
     - Stores session keys:
       * `$_SESSION[ADMIN_SESSION] = true`
       * `$_SESSION['vortex_admin_id'] = $user['id']`
       * `$_SESSION['vortex_admin_user'] = $user['username']`
       * `$_SESSION['vortex_admin_role'] = $user['role']`
       * `$_SESSION['admin_ip'] = get_client_ip()`
       * `$_SESSION['admin_user_agent'] = $_SERVER['HTTP_USER_AGENT']`
  6. Audit Log:
     - Writes to `admin_activity_logs` (`action = 'login'`, `details = 'Successful login'`).
     - Updates `last_login` timestamp and increments `login_count` in `admin_users`.
  7. Redirects to `/admin/dashboard.php`.
```

## 4. REST API SPECIFICATIONS (MICRO-LEVEL)

### 1. Contact Form API Endpoint

- **Route**: `POST /api/contact.php`
- **Content-Type**: `application/x-www-form-urlencoded` OR `multipart/form-data`
- **Authentication**: Public (CSRF Token & Honeypot Protected)
- **Rate Limit**: 5 requests per 300 seconds per IP address

#### Request Parameters
| Parameter | Type | Required | Description / Validation |
|---|---|---|---|
| `fullName` / `name` | String | Yes | Full name of the submitter (Max 120 chars) |
| `emailAddr` / `email` | String | Yes | Valid email address (`FILTER_VALIDATE_EMAIL`) |
| `phone` | String | No | Phone number (Regex `^[\+0-9\-\s\(\)]{7,20}$`) |
| `service` | String | No | Target service category (Default: "General Inquiry") |
| `company` | String | No | Submitter's company or organization name |
| `msgText` / `message` | String | Yes | Inquiry message text (Min 10 chars, Max 5000 chars) |
| `csrf_token` | String | Yes | CSRF verification token matching active session |
| `website_hp` | String | No | Anti-spam honeypot (Must be empty) |

#### Response Payloads
```json
// Success Response (HTTP 200 OK)
{
  "success": true,
  "message": "Thank you! Your message has been sent. Our team will reply within 24 hours.",
  "inquiry_id": 142
}

// Error Response - Validation (HTTP 200 / 400)
{
  "success": false,
  "message": "Please enter a valid email address."
}

// Error Response - Rate Limit (HTTP 200 / 429)
{
  "success": false,
  "message": "Too many requests. Please wait a few minutes before trying again."
}
```

## 5. DATABASE SCHEMA & DATA DICTIONARY

The system runs on MySQL 8.0 / MariaDB (Database: `u696371114_vortexsoftcom`) with full UTF-8 MB4 charset support.

### Table 1: `contact_inquiries`
Stores all inbound business leads and customer service requests.
```sql
CREATE TABLE `contact_inquiries` (
  `id`           INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `name`         VARCHAR(120) NOT NULL,
  `email`        VARCHAR(180) NOT NULL,
  `phone`        VARCHAR(30)  DEFAULT NULL,
  `service`      VARCHAR(120) DEFAULT 'General Inquiry',
  `company`      VARCHAR(120) DEFAULT NULL,
  `message`      TEXT         NOT NULL,
  `ip_address`   VARCHAR(45)  DEFAULT NULL,
  `user_agent`   VARCHAR(255) DEFAULT NULL,
  `source_page`  VARCHAR(255) DEFAULT NULL,
  `is_read`      TINYINT(1)   NOT NULL DEFAULT 0,
  `is_replied`   TINYINT(1)   NOT NULL DEFAULT 0,
  `notes`        TEXT         DEFAULT NULL,
  `created_at`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  INDEX `idx_email` (`email`),
  INDEX `idx_is_read` (`is_read`),
  INDEX `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### Table 2: `job_applications`
Tracks candidate resumes and the multi-stage recruitment pipeline.
```sql
CREATE TABLE `job_applications` (

  `expected_ctc`     VARCHAR(60)   DEFAULT NULL,
  `resume_filename`  VARCHAR(255)  DEFAULT NULL,
  `resume_path`      VARCHAR(500)  DEFAULT NULL,
  `cover_letter`     TEXT          DEFAULT NULL,
  `linkedin_url`     VARCHAR(300)  DEFAULT NULL,
  `portfolio_url`    VARCHAR(300)  DEFAULT NULL,
  `ip_address`       VARCHAR(45)   DEFAULT NULL,
  `status`           ENUM('new','reviewed','shortlisted','interview','offered','rejected','withdrawn') NOT NULL DEFAULT 'new',
  `admin_notes`      TEXT          DEFAULT NULL,
  `consent_given`    TINYINT(1)    NOT NULL DEFAULT 1,
  `consent_timestamp`DATETIME      DEFAULT CURRENT_TIMESTAMP,
  `created_at`       DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`       DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

## 8. SECURITY HARDENING & DEFENSE-IN-DEPTH

### 1. HTTP Security Headers (Configured in `.htaccess` & `header.php`)
- `X-Frame-Options: SAMEORIGIN`: Prevents clickjacking by blocking unauthorized framing.
- `X-Content-Type-Options: nosniff`: Prevents MIME-sniffing exploits.
- `X-XSS-Protection: 1; mode=block`: Activates native browser XSS filtering.
- `Referrer-Policy: strict-origin-when-cross-origin`: Controls referrer header exposure.
- `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`: Enforces strict HTTPS communication.
- `Permissions-Policy`: Restricts camera, microphone, and payment APIs to unauthorized third parties.
- `Content-Security-Policy (CSP)`: Whitelists approved CDNs (jsDelivr, Cloudflare, Google Fonts) and restricts malicious script execution.

### 2. Database & Application Layer Protection
- **SQL Injection Prevention**: 100% of SQL statements across all APIs and admin modules execute via PDO prepared statements with parameterized binding.
- **Cross-Site Scripting (XSS)**: All user inputs pass through `htmlspecialchars(strip_tags(trim($input)), ENT_QUOTES, 'UTF-8')`.
- **Cross-Site Request Forgery (CSRF)**: Cryptographically secure random tokens generated via `bin2hex(random_bytes(32))` and validated with `hash_equals()`.
- **Upload Directory Hardening**: Direct execution of `.php`, `.phtml`, `.cgi`, `.sh`, `.exe` scripts is disabled inside `/uploads/` via Apache handler overrides.
- **Access Protection**: Direct HTTP access to `/config/`, `/includes/`, `/database/`, `/backups/`, and `/uploads/resumes/` is blocked via 403 Forbidden rewrite rules.

## 10. CI/CD WEBHOOK & AUTO-DEPLOYMENT PIPELINE

- **Webhook Endpoint**: `POST /admin/webhook_deploy.php`
- **Authentication**: Token verification via `HTTP_X_DEPLOY_TOKEN` header or `?token=` parameter matching `DEPLOY_TOKEN`.
- **Execution Mechanism**:
  1. Validates deployment token using `hash_equals()`.
  2. Creates temporary working folder in `/uploads/temp/`.
  3. Downloads latest repository archive from GitHub (`codeload.github.com/Aniketmadhukarraokadam/VORTEXSOFTINNOVATIONSMAIN/zip/refs/heads/main`) using cURL with SSL fallback.
  4. Extracts ZIP archive via `ZipArchive`.
  5. Recursively synchronizes files to `public_html` root directory, excluding development-only files (`.git`, `.github`, `package.json`).
  6. Cleans up temporary archives and folders.
  7. Writes deployment timestamp and files copied count to `/admin/deploy.log`.
  8. Returns instant JSON response (`{"success": true, "files_copied": 240, "timestamp": "2026-08-26 09:43:00"}`).
